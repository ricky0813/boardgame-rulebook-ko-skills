# 작업 상태와 산출물

프로젝트의 기존 디렉터리 관례가 있으면 그 이름을 사용한다. 새 프로젝트라면 아래 산출물을 만들고 계획 문서에서 실제 경로를 연결한다. 파일명만 만들고 내용은 비워 두지 않는다.

| 단계 | 최소 산출물 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 계획 | `plan.md`, `progress.md`, 원본 목록·판본·에라타 확인 기록·물리/인쇄 쪽 대응표·표지 게임 타이틀 선택 | 입력·판형·쪽수·검토 단위가 확인되고 계획에 대한 사용자 승인 기록이 있음 |
| 용어 | `glossary.md`, 판본 차이·미해결 이슈 | 기존 한국어판의 확정 용어와 신규 용어가 구별되고 용어·판본 대조에 대한 사용자 승인 기록이 있음 |
| 번역 | 전 쪽을 포괄하는 영한 대조 원고와 카드/영역 색인 | 원본 이미지의 모든 번역 대상 문구가 대응되고 전체 번역 원고에 대한 사용자 승인 기록이 있음 |
| 자산 | 모든 인쇄 쪽의 원본 렌더, 분할 페이지, 아이콘/이미지 파일·목록·연락판, 보존/삭제 지도, 개선한 이미지의 출처·방법·비교 기록, 선택한 경우 한국어 표지 타이틀 이미지와 적용 미리보기 | 페이지별 자산의 출처·의미가 확인되고 쪽수 대응과 자산 준비 결과에 대한 사용자 승인 기록이 있음 |
| 개별 쪽 | 그 쪽 PDF, 원본/한국어 나란히 비교한 PNG, 검수 로그 | PDF·비교 이미지·검수 결과를 제시한 뒤 해당 페이지에 대한 사용자 승인 기록이 있음 |
| 최종 | 승인된 전 쪽 합본 PDF와 최종 검수 기록 | 쪽수·판형·검색 텍스트·시각 검수가 통과하고 최종 합본에 대한 사용자 승인 기록이 있음 |

`progress.md`에는 단계별 작업 상태(`미착수/진행 중/완료`), 산출물 링크, 남은 문제와 별도의 사용자 검토 상태(`미제시/사용자 검토 중/수정 중/승인`)를 적는다. 승인 근거가 된 사용자 발언과 범위도 기록한다. 작업 완료만으로 다음 단계에 진입하지 않는다. 페이지 표에는 최소한 `인쇄 쪽`, `원본 PDF 물리 페이지/좌우`, `번역 상태`, `자산 상태`, `조판 PDF`, `비교 PNG`, `검수 문제`, `사용자 상태`를 둔다. 사용자 상태는 `미조판 → 사용자 검토 중 → 수정 중 → 승인 → 합본 반영`으로 관리한다. 사용자의 진행 지시 또는 명시적 확인이 없는 단계나 쪽을 승인으로 바꾸지 않는다. 사용자가 명시적으로 허용한 일괄 진행·승인 생략 범위는 해당 기록을 근거로 따른다.

다른 컴퓨터/세션에서 재개할 때는 마지막 메시지만 믿지 말고 이 표의 경로를 실제 파일과 대조한다. 예전 비교 PNG나 합본만 있고 최신 페이지 PDF가 없으면 완료로 간주하지 않는다.

에라타, 번역 원고, 이미지 자산이 바뀌면 영향을 받는 페이지와 합본을 `재생성 필요`로 표시한다. 새 페이지 PDF·비교본·합본의 경로 또는 해시가 이전 승인 기록과 다르면 변경 내용을 검토하고 사용자에게 필요한 범위만 다시 제시한다. 실제 승인 대상이 변하지 않은 상태 기록·파일명 정리는 재승인 사유가 아니다.
